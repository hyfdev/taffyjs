# @taffyjs/yoga Implementation Reference

This is the implementation reference for the current draft @taffyjs/yoga package. It records the audited Yoga 3.2.1 surface, evidence, derived constraints, and the implemented compatibility boundary; only judgments explicitly accepted by Yunfei belong in [the decision ledger](taffyjs-yoga-decisions.md). The public summary lives in the package's [compatibility guide](../../packages/taffyjs-yoga/COMPATIBILITY.md).

| P1       | Verification and release gate                      | Complete | Repository consumer, declaration, differential-oracle, failure-injection, package-boundary, cleaned-output, and full repository gates cover the implementation plan.                                                                                      |
| P2       | Performance evolution boundary                     | Deferred | Later cache, batch, selective-query, or compact-transport work remains semantically possible. Representative end-to-end workloads and retained measurements are required before choosing an optimization; this is not part of Yoga compatibility closure. |

The P0 ownership design must reject a normal create, insert, remove, detach, or free path that implicitly reconstructs or migrates an entire subtree or all unrelated roots. Operations whose meaning requires traversal, such as freeRecursive, are exempt. Style and topology changes must not implicitly compute layout; calculateLayout remains the explicit calculation boundary.

Internal file splitting, private class names, code generation versus handwritten code, exact error wording, benchmark thresholds, a named external consumer, and multi-version Yoga support are deliberately deferred unless earlier research makes one of them necessary to settle a P0 boundary. Browser and WASM support are excluded: @taffyjs/yoga is permanently the Node package over @taffyjs/node; any future WASM implementation would use a separate package.

## Classification rules

Every evaluated public capability uses Compatible, Different, or Unsupported. Required implementation fixtures and release evidence are tracked separately and do not weaken a classification back into an ambiguous status.

- Compatible means the same supported Yoga source call and public value shape can provide the core function and normal observable behavior consumers rely on through bounded JavaScript or TypeScript mapping over the current @taffyjs/node API. It does not mean total replication of callback invocation traces, JavaScript proxy identity, internal cache or recomputation choices, exact error text, post-free access, double-free behavior, or other incidental implementation artifacts; such a detail becomes a compatibility target only when real consumer evidence makes it material.
- Different means the same source call remains available and produces credible, stable Taffy semantics, but a specific observable result differs from Yoga and must be stated with its trigger.
- Unsupported means no credible semantics can be provided inside the JavaScript-only boundary; a whole unsupported method or export is omitted, while a dynamically supplied unsupported value is rejected at runtime.

API shape, accepted input, stored getter value, state transition, error behavior, and calculated layout are separate observable capabilities when their classifications differ. A general setter is not marked Different merely because some separate style combination exercises a known Yoga/Taffy algorithm difference; that combination receives its own row.

## Package entries and exports

The decided package is ESM-only, follows @taffyjs/node's supported Node.js version (currently Node.js >=22.18), and mirrors both Yoga entry shapes at @taffyjs/yoga and @taffyjs/yoga/load. It never provides browser or WASM support.

Yoga 3.2.1 is ESM and publishes two package entries.

| Entry            | Runtime exports                                           | Type-only exports                                        | Loading behavior                                                                       |
| ---------------- | --------------------------------------------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| yoga-layout      | One default Yoga object and 18 named numeric enum objects | Config, DirtiedFunction, MeasureFunction, and Node       | Eagerly loads the bundled WASM assembly with top-level await.                          |
| yoga-layout/load | loadYoga plus the same 18 named numeric enum objects      | Config, DirtiedFunction, MeasureFunction, Node, and Yoga | loadYoga asynchronously creates and returns a Yoga object. There is no default export. |

The default Yoga object contains Config and Node factory objects plus 72 uppercase numeric constants corresponding to every member of the 18 named enums. Config and Node are not named runtime exports from either entry; their names are exported only as types, while the runtime factories are Yoga.Config and Yoga.Node.

The wrapper uses three structural result types that are public through method signatures but are not exported by name: Layout has left, right, top, bottom, width, and height numbers; Size has width and height numbers; Value has unit and value fields.

A runtime reflection check against the published 3.2.1 package found the same eight Config and 100 Node prototype method names as the declarations, with no missing or extra prototype method; it also confirmed 18 named runtime enums and 72 legacy constants. Intentional differences in accepted arguments, defaults, or return values still require behavioral probes because method-name equality does not prove behavioral equality.

### Dependency substitution

The unchanged-import mechanism is a standard package-manager alias. A published consumer can retain `import Yoga from "yoga-layout"` and `import { loadYoga } from "yoga-layout/load"` while declaring `"yoga-layout": "npm:@taffyjs/yoga@<version>"`. [npm package aliases](https://docs.npmjs.com/cli/using-npm/package-spec#aliases) install one registry package under another local dependency name, and [pnpm aliases](https://pnpm.io/aliases) document the same no-source-change replacement behavior.

The repository consumer fixture exercises the local package before publication with `"yoga-layout": "workspace:@taffyjs/yoga@*"`; [pnpm documents this exact workspace-alias form](https://pnpm.io/workspaces#referencing-workspace-packages-through-aliases) and rewrites it to a normal npm alias when a package is packed. The official Yoga oracle therefore uses the separate test-only alias `"yoga-layout-oracle": "npm:yoga-layout@3.2.1"`. Committed fixtures prove unchanged root and `/load` imports through the built workspace package. An actual registry-alias installation remains a post-publication smoke test; the repository does not add a tarball-install test path for this package.

## Capability matrix

This matrix answers whether the public capability has a credible implementation over the current @taffyjs/node boundary. It does not claim that every Flex layout produced after a compatible setter is pixel-identical to Yoga. Setter storage and getter round trips, calculation mechanics, and the resulting layout are classified separately so that an algorithm difference does not incorrectly make a useful API unsupported.

No first-release feasibility blocker remains in the inventoried Yoga 3.2.1 surface. The grouped result is:

- Package entries, factories, ordinary Config state, tree ownership and mutation, declaration getters and setters, calculation on any live Node, logical dirty and new-layout flags, ordinary measure callbacks, Yoga-shaped computed output, and per-Node point-grid rounding are Compatible through bounded JavaScript or TypeScript mapping.
- Yoga cache artifacts, MeasureMode-sensitive or flex-basis-sensitive measurement results, aspect-ratio layout, min/max combined with flex growth or shrinkage, main-axis auto margins combined with justification offsets, and the documented reversed-axis, overflowing, or zero-size distribution cases are Different. The same API remains callable and returns Taffy's stable geometry under the documented trigger.
- Display.Contents, PositionType.Static, non-None Errata values, reference-baseline selection, property-invalid Align values, positive or negative infinite calculation owner dimensions, and undeclared broken setter coercions are Unsupported. Omit a wholly unsupported member where practical and always reject it at runtime.

### Calculation context for the selected node

Yoga's calculateLayout width and height are not merely maximum available space. For an axis with no definite declared size or declared maximum, a finite argument gives the selected Node an exact outer constraint; for example, an empty Yoga Flex root calculated with width 100 has computed width 100, while the same Taffy Flex root given AvailableSpace.Definite(100) has width zero. A measured Yoga root likewise receives Exactly(100) and finishes at width 100, whereas an unmodified Taffy measured root remains at its measured width.

The bounded bridge is to derive a calculation-only Taffy Style for the selected Node. A Yoga exact root constraint becomes an effective exact Taffy size after resolving the selected Node's margins, padding, border, box sizing, min/max constraints, and percentage bases from the calculateLayout owner inputs. A Yoga declared maximum remains a fit-content bound rather than becoming an exact size. Root declarations remain unchanged and all descendants continue through the ordinary Taffy algorithm. The selected Node's ordinary derived Style is restored in a finally path after native calculation; restoring it may leave broader native dirty state, which is internal under the decided calculation-state model. This translation applies equally when the selected Node is still attached because Taffy can calculate any NodeId as the root of one invocation without moving it.

This temporary Style is calculation context, not a second declaration or layout engine: Yoga getters continue to read the one declaration state, callback closures see that state, and Taffy alone computes geometry. A successful calculation projects and commits outputs for the selected subtree; a thrown measurement leaves the previous Yoga-shaped outputs and logical dirty state intact, while a first failed calculation retains the initial zero-position and NaN-size output.

### Measure callback bridge

One facade-level Taffy measure closure dispatches by NodeId to the callback stored on the Yoga Node. Nodes without a Yoga callback return the ordinary zero intrinsic size. The adapter converts each Taffy request independently: a known dimension becomes Yoga MeasureMode.Exactly, finite available space becomes MeasureMode.AtMost, MaxContent becomes MeasureMode.Undefined with NaN, and MinContent becomes MeasureMode.AtMost with zero. Taffy's known dimensions can contain an outer border-box size, while the matching finite available-space value has padding and border removed, so the adapter uses that content-box value for Exactly. Every finite content-box value is clamped to zero rather than exposing a negative constraint. The calculation context also marks each finite exact axis on the selected measured root, because Taffy's final leaf request can otherwise retain only a finite available-space value. Taffy adds padding and border back to the measured result.

This conversion is intentionally not a reconstruction of Yoga's measurement phases. Taffy can make several intrinsic, sizing, and final-layout requests where Yoga makes one, and AvailableSpace.Definite does not record whether its source was an exact stretch or a fit-content bound. Consulting parent Flex state to synthesize Yoga's call sequence would duplicate algorithm logic and is outside the JavaScript-only boundary. Callback count, order, and exact argument trace therefore remain unspecified, and a callback that changes its result based on MeasureMode can produce a documented Different layout.

The callback result is converted to numbers, missing dimensions become NaN, and each NaN or negative dimension is normalized to zero before returning to Taffy; positive infinity remains positive infinity, matching Yoga's normalizer. A thrown JavaScript value is rethrown with identity preserved. The current @taffyjs/node binding marks the calculation subtree dirty after callback failure, so a later calculation can retry. Replacing or removing the retained callback also marks only the private native node dirty, leaving Yoga-visible dirty state unchanged while ensuring that the next calculation uses the current registration; Yoga 3.2.1 instead reuses its stale cached measurement in the pinned fixture, which is a documented cache-artifact Difference. Measured Nodes must remain leaves, markDirty remains restricted to measured leaves, and native TaffyTree access attempted reentrantly during the callback can throw the existing tree-busy error; exact callback reentrancy is not part of the compatibility promise.

There is one performance boundary to preserve. Once a calculation uses computeLayoutWithMeasure, the current @taffyjs/node boundary invokes the JavaScript closure for every Taffy leaf request, including leaves without a Yoga callback; a bounded 100-leaf probe observed 200 calls for fixed-size leaves and 400 for intrinsically sized leaves. A committed path-selection profile confirms that a selected subtree without a measured Node invokes ordinary computeLayout once and never enters computeLayoutWithMeasure, while adding a measured Node selects the measured entry. The remaining mixed-tree overhead is not a correctness blocker and does not justify shadow topology or JavaScript Flex logic; it belongs in later end-to-end performance work.

### Yoga-shaped output projection

Taffy's unrounded Layout is the geometry source, but it is not returned directly. After a successful calculation the facade traverses the selected subtree once and stores Yoga-shaped output records. This projection is required even when the numeric geometry matches because Yoga exposes only left, right, top, bottom, width, and height, retains last-calculated results separately from declarations, and gives right and bottom semantics that are not simply the unused space after the Node.

For each non-root Node, Taffy's physical location supplies the unrounded left and top. The parent flex and cross axes determine which physical edge Yoga treated as flex-start: when it is Left or Top, that edge receives the Taffy location; when it is Right or Bottom, the edge is derived from the parent size, child size, and physical location. The opposite edge retains Yoga's resolved margin plus relative-inset initialization. This reproduces Yoga's observable behavior such as a normal-flow right value remaining the trailing margin rather than parentWidth - left - width. The selected root has no parent-placement step, so all four positions are resolved from its own margins and relative insets under the calculation owner inputs. Static-position containing-block traversal does not need to be reproduced because PositionType.Static is unsupported.

Pixel-grid processing then follows Yoga's algorithm over absolute unrounded left and top. Each Node uses its own Config pointScaleFactor; only left, top, width, and height are rounded; a Node with a measure function uses Yoga's ceil-sensitive text-size branch; right, bottom, margin, padding, and border remain unrounded. JavaScript must apply Yoga's 0.0001 comparison tolerance and Math.fround at the stored float boundaries. Mixed factors in one tree are therefore supported without using Taffy's tree-wide rounding.

Computed physical margin, padding, and border values come from the unrounded Taffy Layout. Start and End select the physical side from the calculated direction, and an auto-margin declaration reports zero even when Taffy stores the distributed physical margin. Horizontal, Vertical, and All remain invalid computed-getter inputs. New and reset Nodes start with zero positions, NaN width and height, and zero computed edges; removing a child resets that child's output while preserving its declaration state. Output records are committed only after the native calculation and complete projection succeed.

The first implementation may read topology and unrounded Layout one Node at a time. Later @taffyjs/node batch reads, selective queries, or compact complete-Layout transport can reduce boundary calls and object construction without changing any Yoga declaration, calculation, or output rule here. Those are transport optimizations, not part of Yoga compatibility semantics.

### Decided ownership and lifecycle mapping

A Yoga facade means the default Yoga object exported by one loaded module or the Yoga object returned by one loadYoga() call. It is an isolated object space, not one layout root: a facade can contain many detached nodes and many unrelated roots. Yoga 3.2.1 creates a separate WASM assembly and separate Node and Config classes for each loadYoga() call, rejects cross-assembly objects, and permits nodes with different same-facade Config values to appear in one tree.

The decided model is one private facade runtime with one TaffyTree. Every live Yoga Node receives one stable NodeId in that tree at creation and keeps it through attachment, detachment, reset, and calculation. A TaffyTree already holds multiple disconnected roots, so it directly represents the facade's node forest without any extra partitioning or subtree migration.

| Internal Config state              | Yoga options, current values, and translation/cache revisions. Nodes retain it strongly, so an early public Config.free cannot leave a dangling reference. The state becomes unreachable only after the public handle and every Node using it are gone.                                                                       |
| Optional implementation-only cache | A parent pointer or last translation revision may avoid repeated native queries. Taffy topology remains authoritative, and such a cache is updated only after the corresponding native mutation succeeds; it cannot independently authorize topology.                                                                         |

The high-level ownership and operation mapping are fixed implementation references. Durable fixtures cover pre-commit failure atomicity, post-commit callback-error behavior, and the stated transitions:

| Operation                         | Mapping                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Node creation                     | Allocate the canonical wrapper and native NodeId immediately. createDefault and create without a Config use the facade's immortal default Config state; createWithConfig retains the supplied same-facade state.                                                                                                                                               |
| insertChild                       | Prevalidate live same-facade handles, index, one-parent ownership, measured-parent restriction, and cycles. Mutate Taffy once; only then update any parent cache and Yoga-visible dirty flags. Different Config states are allowed in one subtree.                                                                                                             |
| removeChild                       | A non-child is a no-op. A real child is detached without being freed; its Style, Config, callbacks, identity, and logical dirty flag survive, while its Yoga-shaped computed output resets to zero positions and NaN dimensions. Internally dirty the detached native node if necessary so a later standalone calculation does not reuse parent-context cache. |
| Node.copyStyle                    | Copy the source's normalized Yoga Style declaration state while retaining the destination's Config, topology, callbacks, and identity. Mark the destination's derived Taffy Style pending and its visible state dirty only when the declaration state changes.                                                                                                 |
| Node.free or Node.destroy         | Invalidate and remove exactly that Node. If attached, detach it and dirty the surviving parent chain. Detach direct children as independent live roots while preserving each child's subtree, identity, Style, Config, callbacks, public state flags, and last public output.                                                                                  |
| Node.freeRecursive                | Collect and remove the selected Node and all descendants in postorder. References to every removed wrapper become invalid. Only an outside parent, when present, survives and becomes dirty.                                                                                                                                                                   |
| Node.reset                        | Require a live detached leaf, preserve its NodeId and internal Config state, then replace every other Node-owned input and callback with construction defaults based on the Config's current value. Set logical dirty and new-layout to true and reset public geometry to zero positions and NaN dimensions.                                                   |
| Config.free or Config.destroy     | Invalidate the public handle and reject future methods or Node construction through it. Existing Nodes safely retain the last Config state until they are freed; this is ordinary retained ownership, not a second public Config object.                                                                                                                       |
| Any method through a freed handle | Throw a deterministic JavaScript error before native access. Exact Yoga use-after-free, double-free, and Embind pointer-alias behavior is outside the core compatibility target.                                                                                                                                                                               |

Several Yoga 3.2.1 implementation artifacts are intentionally excluded by the accepted core-compatibility principle. getChild and getParent create additional Embind proxy objects rather than preserving JavaScript identity; freeing through one proxy can leave another proxy addressing freed memory; freeing an attached Node removes it from the parent without marking that parent dirty; freeing Config before its Nodes leaves dangling native pointers; and reset loses the callback context needed to install a later measure function. The facade instead returns one canonical wrapper, invalidates it reliably, preserves safe retained Config state, dirties surviving topology, and permits callbacks after reset.

This model does not duplicate layout. JavaScript retains only public compatibility inputs, handles, flags, callbacks, and projected outputs; Taffy remains the only topology authority and geometry calculator. Normal create, attach, detach, reset, and single-node free never reconstruct or migrate a subtree. Fixtures cover pre-commit failure atomicity, post-commit callback errors, poisoning after an unexpected partial multi-step native failure, exact computed-output transitions, facade isolation, same-tree reentrancy during measure callbacks, and native-authoritative topology.

### Decided Yoga declaration-state model

The Yoga-facing state is the normalized declaration produced by a Yoga setter, not the caller's original JavaScript token and not the final values used by layout. For example, setWidth("50%") and setWidthPercent(50) produce the same Yoga declaration, while an unset field, an explicit auto value, and a resolved numeric default may remain distinct even when they currently lay out the same way.

Treating the stored Taffy Style as the only source for Yoga getters and later mutations is not lossless:

| Yoga state area                       | Information lost by the Taffy Style representation                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| position, margin, padding, and border | Yoga stores nine independent declarations per family: Left, Top, Right, Bottom, Start, End, Horizontal, Vertical, and All. Taffy stores four resolved physical sides. The original precedence and fallback declarations cannot be reconstructed.                                                                                                                                                                                                                                     |
| gap                                   | Yoga stores Column, Row, and All independently; Taffy stores two resolved axes.                                                                                                                                                                                                                                                                                                                                                                                                      |
| flex shorthand and longhands          | Yoga stores flex, flexGrow, and flexShrink as independent optional numbers and flexBasis as a separate tagged length. The JavaScript API has setFlex but no getFlex, yet the stored flex value remains observable through later longhand resets, copyStyle, and layout. Taffy has no flex shorthand and stores only concrete grow, shrink, and basis values. Unset and explicit zero have different fallback behavior even though Yoga getters can currently return the same number. |
| dimensions and flex basis             | Yoga distinguishes Unit.Undefined from Unit.Auto. Taffy's public Dimension has Auto but no Undefined, and Taffy materializes defaults for min and max sizes.                                                                                                                                                                                                                                                                                                                         |
| direction                             | Yoga stores Inherit and resolves it from the calculation direction and ancestor state. Taffy Style stores only Ltr or Rtl. Start and End edge resolution therefore also depends on declaration state outside the final four-sided Rect.                                                                                                                                                                                                                                              |
| Config-sensitive defaults             | useWebDefaults changes construction and reset defaults and the resolved flex-shrink default. copyStyle copies Style but retains the destination Config, so copying an unset flexShrink from a normal-default node to a web-default node changes the getter from 0 to 1. A resolved Taffy number cannot preserve that distinction.                                                                                                                                                    |

The current @taffyjs/node setStyle operation replaces the complete native Style and applies Taffy defaults to omitted fields. A minimal overlay would therefore split one logical Yoga Style between JavaScript metadata and native Taffy fields: getters, copyStyle, reset, dirty comparison, and every complete native update would have to merge both sources. The lossy categories already cover most value-bearing Yoga declarations, so that split is more complex than retaining one complete logical Yoga declaration model.

The decided model is that each Node owns one complete logical Yoga declaration state and its Config reference. A derived Taffy Style is produced from that state, the effective direction, and supported Config behavior, then synchronized to the NodeId before native calculation. Yoga setters and declared-style getters operate on the Yoga state; Taffy remains authoritative for topology and computed layout. This is an input model plus a derived native representation, not a second layout engine.

The declaration state is mutable current state, not an immutable snapshot that becomes stale after a setter. A successful setter updates it synchronously and advances a conceptual style revision. Dirty means that the last applied Taffy Style or calculated Layout represents an older revision: declared-style getters immediately return the new declaration, while computed-layout getters continue to return the last calculated output until calculateLayout runs. Yoga 3.2.1 exhibits this directly: after a calculated width of 100, setWidth(200) makes getWidth return 200 and isDirty return true while getComputedWidth remains 100; the next calculation changes the computed width to 200 and clears dirty.

Complete logical state does not require eagerly allocating a large nested JavaScript object for every Node. The physical representation may share defaults, store only deviations, use fixed compact slots, or use another bounded representation as long as it preserves every supported declaration and has one owner. The eager-versus-lazy native synchronization schedule and memory representation remain performance choices to validate with representative node counts; they are not part of the semantic model.

## Intentional JavaScript wrapper behavior

The Yoga JavaScript wrapper adds observable behavior beyond forwarding the declarations to WASM.

- It patches setPosition, setMargin, setFlexBasis, setWidth, setHeight, setMinWidth, setMinHeight, setMaxWidth, setMaxHeight, setPadding, and setGap to inspect the last argument and route point, percent, and auto values to the unit-specific native method. An auto value is rejected when that method family has no Auto variant.
- For non-object values, the patched setters choose percent only when a string ends with a percent sign and otherwise choose point, then use parseFloat. This admits runtime inputs beyond the narrower declarations and makes malformed strings, NaN, and undefined behavior part of the later compatibility check.
- The patched setter code also attempts to accept an object by reading its unit and valueOf result, while the TypeScript declarations do not include Value objects in these setter inputs. The wrapper source comment claims getter-to-setter round trips, but the published 3.2.1 Value is a plain object and a getWidth-to-setWidth probe resets the declaration to Unit.Undefined; this accidental input is excluded.
- setMeasureFunc accepts null by routing it to unsetMeasureFunc, and the wrapper converts a missing measured width or height to NaN before returning to Yoga.
- setDirtiedFunc converts the JavaScript function to the WASM callback representation.
- Config.free and Node.free call the corresponding destroy factory.
- Node.create selects createWithConfig or createDefault from the optional argument.
- freeRecursive repeatedly frees the first child and then frees the current node.
- calculateLayout supplies NaN for omitted width and height and LTR for an omitted direction at runtime, although its TypeScript declaration makes the first two arguments required while allowing explicit undefined.

These wrapper behaviors are part of the compatibility inventory. A generated declaration alone is therefore insufficient as the @taffyjs/yoga reference.

## Upstream declaration and runtime mismatches

For supported APIs, @taffyjs/yoga preserves Yoga 3.2.1's published declaration shape so existing TypeScript source still compiles, and separately implements the selected runtime behavior below. The only deliberate runtime corrections are the dirtied callback argument and null handling described in the capability matrix; unsupported inputs are rejected instead of entering Yoga's accidental coercion paths.

- getGap is declared to return Value, but the C++ wrapper returns float. The published runtime returns a plain number for both point and percent gaps and does not preserve Unit in the result.
- setGap and setGapPercent are declared to return Value, but the C++ setters return void and the published runtime returns undefined.
- getChild is declared to return Node, but the C++ wrapper returns a null pointer for an out-of-range index and the published runtime exposes that as null.
- DirtiedFunction is declared as receiving the dirty Node, but the C++ callback invokes dirtied with no arguments and the published callback receives zero arguments.
- setDirtiedFunc is declared to accept null, but unlike setMeasureFunc the JavaScript wrapper does not route null to the unset method. Setting null succeeds immediately and a later dirty transition throws a TypeError while trying to call the null callback.
- calculateLayout requires width and height arguments in TypeScript while allowing each to be explicitly undefined; the runtime wrapper also permits the arguments to be omitted and supplies NaN, NaN, and LTR defaults.
- The generic setter wrapper attempts to accept Value-like objects and comments that a getter result can be passed back to a setter, but the published Value is a plain object without a numeric valueOf implementation. A published 3.2.1 getWidth-to-setWidth round trip resets the value to Unit.Undefined rather than preserving it.

## Ongoing maintenance

- Re-audit the complete capability matrix before deliberately adopting a Yoga version newer than 3.2.1; no supported release may contain an unclassified method, value, or result trigger.
- Run one actual `yoga-layout` registry-alias installation smoke test after @taffyjs/yoga is published. This cannot be completed against the current private, unpublished package and does not justify a separate tarball-install harness.
- Treat cache, batch, selective-query, compact-transport, and mixed measured-tree overhead as later performance work that requires a representative consumer workload and retained end-to-end measurements.

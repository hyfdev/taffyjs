# @taffyjs/yoga Compatibility

The compatibility baseline is exactly `yoga-layout@3.2.1`. The package is permanently Node-only and ESM-only; it does not provide a browser or WASM backend.

Compatible means the supported API and its useful result match Yoga within the documented input boundary. Different means the API remains available but a named trigger returns stable Taffy geometry or deliberately corrected callback behavior. Unsupported means the package rejects a capability because it cannot provide credible semantics within the JavaScript-only compatibility layer.

## Calculation and computed output

The following calculation and output behavior is Compatible:

Compatible numeric comparisons allow an absolute error below `0.0001` for finite unrounded float fields, matching Yoga's own internal float-comparison tolerance. Rounded point-grid output and the exact fields covered by strict fixtures still compare exactly; this tolerance only covers last-bit differences when Yoga and Taffy evaluate equivalent percentage arithmetic in different float32 steps.

- `calculateLayout()` may select any live Node, including one still attached to a parent. Finite owner dimensions act as Yoga exact outer constraints when the selected Node has no definite declaration or maximum on that axis, without changing the declared Style.
- A successful calculation commits Yoga-shaped output for the complete selected subtree. `getComputedLayout()` and the six scalar layout getters preserve Yoga's left, right, top, bottom, width, and height semantics across LTR, RTL, reversed axes, relative positioning, and absolute positioning.
- `getComputedMargin()`, `getComputedPadding()`, and `getComputedBorder()` support Left, Top, Right, Bottom, Start, and End. Auto margins report zero, and Horizontal, Vertical, and All are rejected.
- Point-grid conversion follows each Node's own Config, including factor zero, mixed factors in one tree, and positive infinity. Computed edges other than left and top remain unrounded, as in Yoga.
- Ordinary fixed and percentage sizes, simple grow and shrink without min/max, and simple nested Flex trees match the pinned Yoga oracle. This is a bounded compatibility corpus, not a universal compatibility percentage.

## Measurement

The normal Measure API is Compatible. `setMeasureFunc()`, `setMeasureFunc(null)`, and `unsetMeasureFunc()` register or remove one synchronous callback on a leaf Node. A measured Node cannot have children, and `markDirty()` remains restricted to measured leaves.

The callback receives Yoga's four arguments and content-box constraints. A known dimension is `Exactly`; a finite soft constraint is `AtMost`; max-content is `Undefined` with NaN; and min-content is `AtMost` with zero. Content-box constraints are never negative. A finite `calculateLayout()` constraint on the selected measured root is treated as `Exactly`, including when padding and border consume all available space. Missing callback result dimensions, NaN, and negative values normalize to zero; values are converted with JavaScript `Number()`, and positive infinity is retained. A thrown value is rethrown without changing its identity.

Measurement failure does not commit partial Yoga-shaped output or public dirty/new-layout flags, and the same calculation can be retried. Measured output uses Yoga's text rounding. Replacing or removing a callback invalidates the private native measurement cache without changing Yoga-visible `isDirty()`, so the next calculation uses the current registration rather than an obsolete result.

An unmeasured selected subtree uses the ordinary native calculation entry and does not enter the JavaScript measurement bridge. Once a selected subtree contains a measured Node, Taffy controls callback count and order and may also request intrinsic sizes for unmeasured leaves. JavaScript-only declaration and computed-output getters remain usable during a callback; a same-facade method that needs native tree access can throw `ERR_TAFFY_TREE_BUSY`. Exact reentrant behavior is not a compatibility promise.

## Unsupported

Unsupported enum members and constants are absent from the TypeScript and runtime surface. If JavaScript supplies their raw numeric values dynamically, the receiving method throws before changing Node or Config state. The same pre-mutation rule applies to the other rejected inputs in this table.

When an upstream enum type also contains values that are Unsupported for one property, the replacement narrows that setter to the supported members. A TypeScript variable or generic that still permits an unsupported member must be narrowed before the call; this is intentional migration feedback. The package exports `AlignContentValue`, `AlignItemsValue`, and `AlignSelfValue` for that purpose. Code that must compile against both Yoga providers can derive the selected provider's type with `Parameters<Node["setAlignItems"]>[0]`. JavaScript and dynamic inputs receive the same check at runtime.

| Capability or input                                                                                                                                             | Public behavior                                                                                                                                                                                                                                  | Reason                                                                                                                          |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------- |
| `Display.Contents` and `DISPLAY_CONTENTS`                                                                                                                       | Omitted; `setDisplay(2)` throws.                                                                                                                                                                                                                 | Taffy 0.13 has no contents box. Credible support would require a second or repeatedly rewritten topology.                       |
| `PositionType.Static` and `POSITION_TYPE_STATIC`                                                                                                                | Omitted; `setPositionType(0)` throws.                                                                                                                                                                                                            | Static containing-block behavior has no direct Taffy representation and is not emulated in JavaScript.                          |
| `Errata.StretchFlexBasis`, `AbsolutePositionWithoutInsetsExcludesPadding`, `AbsolutePercentAgainstInnerSize`, `All`, and `Classic`, plus their legacy constants | Omitted; `setErrata()` accepts only `Errata.None` and throws for any dynamic nonzero value.                                                                                                                                                      | These values select Yoga-specific algorithm branches for which Taffy has no matching switch.                                    |
| `Align` outside the property where it is meaningful                                                                                                             | TypeScript narrows each setter and runtime validation throws before mutation. `setAlignContent` rejects Auto and Baseline; `setAlignItems` rejects Auto and the three distribution values; `setAlignSelf` rejects the three distribution values. | Yoga's incidental fallthrough for property-invalid shared-enum values is layout-dependent and is not a credible style contract. |
| `setIsReferenceBaseline(true)`                                                                                                                                  | The declaration accepts only `false`; dynamic `true` throws.                                                                                                                                                                                     | The current native boundary cannot select Yoga's reference child during baseline calculation.                                   |
| Positive or negative infinity as a `calculateLayout` owner dimension                                                                                            | Throws before calculation or public-state mutation. Finite numbers, `"auto"`, `undefined`, omitted values, and NaN remain supported.                                                                                                             | Yoga's resulting NaN or zero geometry is not a credible available-space contract.                                               |
| Undeclared generic-setter coercions                                                                                                                             | Malformed strings, arbitrary objects, and Value-like getter results supplied to setters throw atomically.                                                                                                                                        | Yoga's broad wrapper coercion is outside its published types and its own getter-to-setter path is broken in 3.2.1.              |

## Upstream work in progress

The compatibility tables describe what the current package can do with its pinned Taffy 0.13 dependency. Upstream work is tracked separately so that a possible path to support is visible without presenting unshipped code as available behavior.

| Capability            | Current classification | Upstream status                                                                                                                                                                                                                   | What must happen before support                                                                                                                                                                                                                                |
| --------------------- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `PositionType.Static` | Unsupported            | [DioxusLabs/taffy#1009](https://github.com/DioxusLabs/taffy/pull/1009) is open as of 2026-08-16. It proposes native `Position::Static` support and the containing-block machinery needed by absolute descendants of static nodes. | The change must ship in a released Taffy version, `@taffyjs/node` must update and expose the needed native capability, and Yoga 3.2.1 differential tests must verify the complete observable behavior. Until then, the Unsupported row above is authoritative. |

An upstream pull request is not a support promise or an ETA. Merging it does not reclassify the capability automatically; adoption and compatibility verification are separate work.

## Known Differences

These rows are deliberate, version-specific differences with regression fixtures:

| Capability and trigger                                                                                            | `@taffyjs/yoga` behavior                                                                                                                                                                               | Yoga 3.2.1 behavior                                                                                                                     |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| Change `useWebDefaults` on a live Config, then calculate a tree whose unresolved shrink values are already cached | Applies the current Config-sensitive Style when the selected calculation reaches Taffy. In the fixture, two 80-point children in a 100-point row become 50/50.                                         | The Config setter does not advance Yoga's cache version, so the same calculation retains 80/80 even though `getFlexShrink()` reports 1. |
| `setDirtiedFunc()` callback argument and `setDirtiedFunc(null)`                                                   | Calls a real callback with its canonical Node after state commit; null unsets the callback.                                                                                                            | Calls a real callback with zero arguments; null is retained and a later clean-to-dirty transition throws a wrapper TypeError.           |
| A min or max constraint combined with Flex growth or shrinkage                                                    | Keeps Taffy's Flex result. The pinned width-120, max-width-90, shrink-1 child in a width-60 Row resolves to 60.                                                                                        | The pinned child resolves to 67.5; other combinations in this result group can likewise follow Yoga's different min/max ordering.       |
| Overlapping physical and logical main-axis margins under a child direction that differs from its parent           | Resolves the declarations to one physical Taffy margin rect. A width-20 RTL child with `margin-left: 4` and `margin-start: 10%` in a width-100 LTR Row remains width 20.                               | Computed margins are also left 4 and right 10, but Yoga's separate Flex margin resolution reduces the child width to 16.                |
| Calculated `aspectRatio`                                                                                          | Keeps Taffy's CSS-oriented aspect-ratio and stretch result. A width-40, ratio-2 child stretched by a 100-by-100 Row is 40-by-100.                                                                      | The same child is 40-by-20.                                                                                                             |
| `WebFlexBasis` disabled while a percentage basis is recalculated under a changed containing size                  | Recomputes the percentage basis. A 50% basis changes from 50 to 100 when its Row changes from width 100 to 200.                                                                                        | Reuses the stale 50-point basis while the experiment is disabled; enabling the experiment produces 100 in both implementations.         |

| Oversized `WrapReverse` lines with distribution-style `alignContent`                                              | Keeps Taffy's line placement.
